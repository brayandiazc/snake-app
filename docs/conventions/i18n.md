# Convenciones de internacionalización (i18n)

> Cómo manejamos múltiples idiomas y locales en Snake App.
> **Última actualización**: 2026-10-13

## Locales soportados

- **Por defecto**: `es`.
- **Adicionales**: `en` neutro.

Los rótulos del marcador (Score, Speed, Record) se traducen como el resto: en español,
Puntos, Velocidad y Récord. La referencia está en inglés, pero la fidelidad es al
aspecto, no al idioma.

## Detección de locale

Orden de prioridad sugerido:

1. Preferencia explícita guardada en `localStorage` (`snake-app:locale`).
2. `navigator.language` del navegador (`es-*` → `es`, cualquier otro → `en`).
3. Locale por defecto.

Sin servidor no hay cabecera `Accept-Language` que leer: el navegador ya la expone en
`navigator.language`.

## Reglas

- Ningún texto visible al usuario se escribe hardcodeado: todo pasa por el sistema de traducción.
- Las claves de traducción se organizan por dominio/feature, no por pantalla.
- Mantener **paridad** entre locales: una clave existe en todos los idiomas soportados.
- Formatos de fecha, número y moneda se localizan según el locale activo.

## Estructura

Un único módulo, porque los textos son pocos:

```text
js/i18n.js   # export const messages = { es: {...}, en: {...} }
```

Los textos que viven en el HTML (título y metadatos) van en `index.html` en español y se
actualizan desde `i18n.js` al cambiar de idioma, junto con el atributo `lang`.

## Ejemplos

```text
# clave de traducción
hud.score: "Puntos"
gameOver.newRecord: "¡Nuevo récord: {score}!"
```

## Comandos útiles

La paridad la verifica una prueba, `tests/i18n.test.js`: falla si una clave existe en un
idioma y no en el otro. Corre con el resto de la suite:

```bash
node --test
```
